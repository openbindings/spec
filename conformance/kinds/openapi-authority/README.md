# OpenAPI authority regressions — 2026-10-05

This repair supersedes the earlier [text-clarification replay](../openapi-text-clarifications.md).
It corrects candidate interpretation and probe behavior using upstream examples
and counterexamples derived from the incorporated authorities. It is not another
independent implementation or a declaration of complete kind support.

Run from the spec root:

```sh
npm ci --prefix conformance/kinds/jsonata --ignore-scripts --no-audit --no-fund
python3 conformance/kinds/openapi-authority/test_authorities.py -v
node scripts/verify-openapi-20-kind.mjs
node scripts/verify-openapi-30-kind.mjs
node scripts/verify-openapi-31-kind.mjs
node scripts/verify-openapi-32-kind.mjs
```

The authority suite has nine test methods. Its portable serialization file has
21 literal cases, exercised in three editions (63 observations). Other methods
include positive and negative subcases. Counts of test methods, observations and
whole native scenarios are different units and must not be added as if equal.

The null `form` case deliberately retains the candidate's explicit precedence
for the OAS style table (`name=`). RFC 6570 treats null as undefined. That tension
is recorded rather than claimed to be unanimous upstream agreement. The 3.0 and
3.1 matrix/label correction is a declared narrow incorporation, not silent
adoption of all later-edition behavior.

## Evidence boundaries

The four native wrappers replay 182, 319, 310 and 73 focused cases/checks/methods,
respectively, plus structural validation of their complete OBI fixtures. Their
READMEs describe the different units and implementation limits. The 3.2 count
fell from 74 because a core-text byte-equality assertion was removed; no
behavioral case was deleted. Each candidate remains hash-gated. The current core
hash is recorded, and current-core fixture shapes are validated separately.

The repair work and independent review uncovered empty-string matrix
serialization, allOf array/required multipart handling and referenced-resource
dialect-context defects; the new corpus now guards those cases. Repairing
expectations to match code would not have resolved these external observations.
Maintainers changed the original independently authored probes in this pass;
their historical authorship does not make these edits independently authored.

Named configuration points, callback/webhook dependencies without `kinds`, and
the three-part source-refusal distinction were reconciled to recorded project
decisions and text-reviewed. This suite does not execute general configuration
negotiation, callback synthesis or complete source-inventory refusal. It also
does not implement general schema translation, recursive multipart, all reference
graphs or a production adapter. Those are explicit evidence gaps.

The pre-kind `conformance/binding-specs` corpus and legacy SDK jobs remain
historical evidence for their own model. Their scenarios have not all been
ported to these candidates. They cannot establish current kind conformance.

Adaptation expressiveness, associated failure data, response negotiation and
header declaration identity remain unresolved design choices. Existing behavior
in those areas was not newly approved by this correctness repair. No readiness
grade or publication qualification follows from these passing checks.
